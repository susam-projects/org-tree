# 004. Дерево показывает и собственную численность, и сумму по поддереву

## Контекст

По заданию дерево показывает у каждого узла `headcount`, а таблица — отдельный
столбец «Всего сотрудников», где «суммарные показатели включают данные узла и
всех его потомков». Формально это разные величины, и первая реализация
следовала букве: дерево брало собственное значение узла, таблица — агрегат.

В split-view обе панели видны одновременно, и расхождение бросается в глаза.
Измерение показало масштаб:

- численность расходится у **16 узлов из 43** — у всех, у кого есть потомки;
- эффективность расходится там же: дерево красило точку по собственному
  `performance` узла, таблица показывала взвешенное среднее;
- у **четырёх узлов из-за этого отличался цвет индикатора**.

Последнее — не косметика. Дивизион «Продажи» имел зелёную точку при собственной
эффективности 74, тогда как взвешенное среднее по поддереву равно 63,1, то есть
жёлтая зона. Дерево показывало подразделение здоровым ровно в тот момент, когда
соседняя таблица показывала его просевшим.

## Рассмотренные варианты

**Оставить как есть.** Заданию формально не противоречит. Но две панели рядом
показывают разные числа и разные цвета для одного подразделения, и объяснить это
пользователю нечем.

**Дерево показывает только агрегаты.** Панели согласуются, точка становится
индикатором здоровья всего подразделения. Собственная численность узла при этом
исчезает из интерфейса совсем, а для дивизиона она и так малоинформативна
(6 человек управленческого состава).

**Дерево показывает оба числа.** Информация не теряется, согласованность
достигается. Строка становится многословнее.

## Решение

Дерево показывает оба числа: `5 / 125 чел.`, где первое — собственная
численность узла, второе — сумма по поддереву. Точка красится по **взвешенному
среднему**, как в таблице.

У листьев оба числа совпадают, поэтому там показывается одно: `12 чел.`
Это 27 узлов из 43, и дублирование на них было бы чистым шумом.

UI-тип дерева переименован так, чтобы величины нельзя было перепутать:
`ownHeadcount`, `totalHeadcount`, `averagePerformance` вместо безымянных
`headcount` и `performance`.

## Последствия

**Хорошее.** Расхождений между панелями нет ни по числам, ни по цвету —
проверено по всем 43 узлам. Имена полей UI-типа теперь сами объясняют, что
именно показывается.

**Цена.** Точка передаёт один цвет, и двух значений в неё не положить, поэтому
симметрии с численностью не получилось: собственная эффективность узла в
интерфейсе не видна нигде. Если она понадобится, самый дешёвый способ —
`title` или `aria-label` на точке с обоими значениями; это заодно закрыло бы то,
что индикатор сейчас передаёт смысл исключительно цветом, без текстовой
альтернативы.

**Замечание.** Расхождение заметил автор при просмотре интерфейса, а не тесты и
не проверка типов. Обе величины имеют тип `number` и обе корректны по
отдельности — поймать такое можно только глазами или тестом, сравнивающим два
представления между собой.
