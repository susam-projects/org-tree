# 003. Split-view медиазапросами, без измерения ширины в JS

## Контекст

Задание предлагает «переключатель Дерево / Таблица (или split-view ≥1280px)».
Выбран split-view, потому что требование «клик по строке выделяет узел в дереве»
осмысленно только тогда, когда обе панели видны одновременно. При одном лишь
переключателе выделение пришлось бы запоминать и проявлять при возврате на другую
вкладку, что сложнее и менее наглядно.

Но ниже 1280px split-view невозможен физически, поэтому переключатель всё равно
нужен — на узких экранах. Требовалось решить, чем определяется текущий режим.

## Рассмотренные варианты

**`matchMedia` в JS.** Компонент подписывается на медиазапрос, хранит в состоянии
`isSplitView` и ветвит разметку. Даёт полный контроль: можно, например, вообще не
монтировать скрытую панель.

Минусы существенные. Появляется второй источник истины о ширине экрана — CSS и
JS, — которые обязаны совпадать; порог `1280px` дублируется в двух местах.
При первом рендере значение ещё неизвестно, что даёт либо вспышку неверной
раскладки, либо дополнительный рендер. Нужна подписка и отписка на изменение.

**Только CSS.** Раскладка полностью определяется медиазапросом, JS о ширине не
знает.

## Решение

Раскладка целиком на медиазапросах. Состояние `view` существует всегда, но выше
порога ни на что не влияет.

```
Panel      display: none | block   по состоянию view
           @media (min-width: 1280px) { display: block }   обе панели

ViewSwitch display: flex
           @media (min-width: 1280px) { display: none }    переключатель скрыт
```

Порог объявлен один раз константой `SPLIT_VIEW_MIN_WIDTH` в файле стилей
дашборда и подставляется во все медиазапросы.

## Последствия

**Хорошее.** Рассинхрона между состоянием и видимым быть не может в принципе:
выше порога видны обе панели независимо от того, что лежит в `view`. Нет вспышки
при первом рендере, нет подписок, порог живёт в одном месте. Смена ширины окна
обрабатывается браузером без единого перерисованного React-компонента.

**Цена.** Скрытая панель всё равно смонтирована и отрисована: ниже 1280px
React рендерит обе, а `display: none` прячет одну. Для 43 строк это ничего не
стоит, но при тысячах строк такой подход стал бы расточительным и потребовал бы
возврата к `matchMedia` или виртуализации.

**Побочное.** Выделение строки продолжает работать и на узких экранах: клик
запоминается, и при переключении на дерево узел уже подсвечен. Это не
проектировалось специально, а получилось бесплатно — именно потому, что логика
не ветвится по ширине.
